<Callout type="info" title="Before you begin">
  You need a DevMate license from [Big Daddy Scripts](https://bigdaddyscripts.com/Products/View/2586/DevMate) and access to your server files and `server.cfg`.
</Callout>

## 1. Download and extract DevMate

Download the latest DevMate release from your [Big Daddy Scripts account](https://bigdaddyscripts.com/Account). Extract the archive into your server's resources directory.

The resource folder must be named exactly `DevMate`:

```text
resources/
└── DevMate/
    ├── fxmanifest.lua
    ├── config.jsonc
    └── permissions.cfg
```

<Callout type="warning">
  Do not rename the `DevMate` folder. Its name is used by licensing and the bundled permission rules.
</Callout>

## 2. Add your license key

Open `DevMate/config.jsonc` and replace the placeholder in `LicenseKey` with the key from the **Licenses** section of your Big Daddy Scripts account.

```jsonc title="DevMate/config.jsonc"
{
  "$schema": "./schemas/config.schema.json",
  "ConfigVersion": 2,
  "MenuCommand": "devmate",
  "LicenseKey": "paste-your-license-key-here",
  // Keep the remaining settings from the included file.
}
```

Keep the license key private. Do not paste it into support messages, screenshots, or a public repository.

## 3. Update server.cfg

Add these lines in this order:

```ini title="server.cfg"
exec @DevMate/permissions.cfg
ensure DevMate
```

The bundled permissions file lets DevMate run the server commands used by Resource Manager and loads the generated filesystem rules used by Resource Explorer.

## 4. Give yourself access

DevMate enables permission checks by default. The included configuration defines `admin`, `developer`, and `tester` groups. Assign your FiveM identifier to one of them in `server.cfg`:

```ini title="server.cfg"
add_principal identifier.license:YOUR_LICENSE_IDENTIFIER group.admin
```

Replace the example identifier with your own. You can use any principal setup supported by FiveM; the group name only needs to match a group in `config.jsonc`.

See [Configuration](/docs/fivem-scripts/devmate/config) before granting Resource Explorer or Code Executor access.

## 5. Start the server

Start or fully restart the server. After DevMate reports that license validation passed, join the server and run:

```text
/devmate
```

If the menu does not open, work through [Troubleshooting](/docs/fivem-scripts/devmate/troubleshooting).

## Updating from v1

DevMate v2 can migrate supported older configuration files to `ConfigVersion: 2`. Before upgrading:

1. Back up your existing DevMate folder.
2. Install the v2 `DevMate` folder without renaming it.
3. Add `exec @DevMate/permissions.cfg` before `ensure DevMate` in `server.cfg`.
4. Start the server and review the migration and licensing messages in the server console.
5. Review your permission groups before allowing anyone to use the menu.

With `AutomaticUpdates` enabled, future resource updates are downloaded and verified automatically. Restart DevMate or the server when the console says an update was installed.
